A high-availability, enterprise-grade access control system designed for mining site safety, automated gate operations, vehicle tracking, visitor management, and real-time security monitoring.

---

## Key Features

- **Automated Gate QR Scanning**: Real-time scanning and evaluation for employees, visitors, vehicles, and equipment with multi-fallback QR decoding.
- **Safety & Compliance Verification**: Automated validation of site induction dates, medical certificates, driver permits, and active status before granting gate clearance.
- **Auto-Direction Detection**: Automatic toggle between `IN` and `OUT` events based on historical entity logs.
- **Security & PII Encryption**: AES-128-CBC field-level encryption for sensitive PII (ID numbers, medical records, visitor names) and PBKDF2/scrypt password hashing.
- **Production Rate Limiting**: Distributed rate-limiting via Redis (`redis://`) with automatic memory fallback.
- **Live Monitoring Dashboard**: WebSocket-based real-time gate log streaming (`Flask-SocketIO`), gate status wallboard, and hardware device heartbeats.
- **SharePoint Integration**: Automatic read-only synchronization of employee rosters and site permits from SharePoint Online.
- **AI Chat Assistant**: Integrated local LLM assistant powered by Ollama or Portkey AI Gateway for site procedure lookups and gate querying.

---

## Tech Stack

- **Core Backend**: Python 3.10+, Flask 3.1.3, Eventlet 0.40.3, Gunicorn 23.0.0
- **Database Layer**: SQLAlchemy 2.0 (Supports Azure SQL / SQL Server in production & SQLite for local development)
- **Real-Time Communication**: Flask-SocketIO 5.3.4, WebSockets
- **Rate Limiting & Caching**: Flask-Limiter with Redis backend support
- **Containerization & Automation**: Docker, Docker Compose, Systemd, Nginx, GitHub Actions

## Quickstart & Setup Guide

### 1. Automated Bootstrap Script
Run the automated setup script to set up virtualenv, install dependencies, create default `.env` with auto-generated secure keys, and run database migrations:

```bash
bash scripts/setup.sh
```

### 2. Manual Setup Steps

If setting up manually:

```bash
# Create virtual environment
python3 -m venv .venv
source .venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Copy environment template & generate keys
cp .env.example .env

# Initialize database
python3 -c "from database import init_db; init_db()"

# Start local development server
python3 app.py
```

Access the web portal at **http://localhost:8080** (Default login: `admin` / `admin` — change immediately on first login).

## Environment Variables Reference

Configuration is managed via `.env`. Refer to `.env.example` for full options:

| Variable | Description | Default / Example | Required |
|---|---|---|---|
| `SECRET_KEY` | Flask session signing key (64-char hex) | `<auto-generated>` | Yes (Prod) |
| `HARDWARE_API_KEY` | Header key (`X-API-Key`) for QR scanner terminals | `<auto-generated>` | Yes (Prod) |
| `FIELD_ENCRYPTION_KEY` | Base64-encoded key for AES-128-CBC PII field encryption | `<auto-generated>` | Yes (Prod) |
| `ADMIN_PASSWORD` | Admin password created on first DB startup | `admin` | No |
| `RESET_ADMIN_PASSWORD` | Set to `true` to force admin password reset | `false` | No |
| `VISITOR_PIN` | 4-digit PIN for self-service visitor registration | `1234` | Yes (Change) |
| `FLASK_ENV` | Environment mode (`production` or `development`) | `production` | No |
| `HTTPS` | Enables secure cookie flag when behind TLS proxy | `false` | Prod |
| `CORS_ORIGINS` | Comma-separated allowed origins for CORS | `*` | Prod (set explicit) |
| `REDIS_URL` | Redis URI for distributed rate-limiting | `redis://localhost:6379/0` | Recommended |
| `DATABASE_URL` | Azure SQL / SQL Server connection string | `mssql+pyodbc://...` | Optional (Prod) |
| `MOBILE_API_KEY` | Secondary API key for mobile scanner app | — | Optional |
| `ENABLE_AI_CHAT` | Enable/disable AI Assistant feature | `true` | No |
| `LOG_LEVEL` | Logging level (DEBUG, INFO, WARNING, ERROR) | `INFO` | No |

## Production Deployment (Bare-Metal / Systemd / Nginx)

For full bare-metal deployment details, consult the [Production Deployment Guide](docs/DEPLOYMENT.md).

- **Systemd Unit**: Located at [`docs/control-access.service`](docs/control-access.service).
- **Nginx Configuration**: Located at [`docs/nginx.conf`](docs/nginx.conf).

```bash
# Copy systemd service
sudo cp docs/control-access.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now control-access

# Copy Nginx config
sudo cp docs/nginx.conf /etc/nginx/sites-available/control-access
sudo ln -s /etc/nginx/sites-available/control-access /etc/nginx/sites-enabled/
sudo systemctl restart nginx
```

## Security Architecture & Best Practices

1. **Password Security**: Passwords are hashed using `pbkdf2:sha256` or `scrypt` via Werkzeug security helpers. Existing legacy plain-text credentials are automatically migrated upon initialization.
2. **Multi-Factor Authentication (MFA)**: TOTP-based two-factor authentication is enforced for admin, manager, and security roles. Users scan a QR code with an authenticator app (Google Authenticator, Authy, etc.) and receive 8 single-use backup codes.
3. **PII Field Encryption**: AES-128-CBC encryption via `cryptography.fernet` protects national ID numbers, medical notes, and visitor names at rest.
4. **Admin Password Persistence**: Admin passwords are set only during initial database seeding and are never overwritten on app restarts unless `RESET_ADMIN_PASSWORD=true` is explicitly passed.
5. **Rate Limiting**: Distributed rate-limiting via Redis prevents brute-force login attempts and scanner terminal flooding.
6. **CSRF Protection**: All browser session state-changing routes require standard CSRF token verification. Header-authenticated API endpoints (`/api/*`) are exempt.
7. **Network Security**: The system requires port 8080 (web UI) and dynamic scanner ports (8081-8200) for hardware device communication. Firewall rules should restrict access to trusted IP ranges only.
